# Проверка на телефоне (М2)

Вход делает сайт внутри приложения; приложение только узнаёт о входе и выходе (`GORODAPP_WEB_SESSION` /
`GORODAPP_WEB_LOGOUT`) и регистрирует телефон для уведомлений.

Уже проверено на симуляторе iPhone (2026-10-22, на тестовой странице вместо сайта — симулятор не выходил в сеть):
ссылки сайта открываются внутри, Instagram / кабинет продавца / `window.open` — в Safari, свайп «назад» и закрытие
«слоя» сайта, `gorodapp://market` (в том числе повторно), нажатие на уведомление (приложение закрыто, свёрнуто,
одно и то же уведомление дважды), экран «Нет связи» и «Повторить».

На телефоне (iPhone через TestFlight, Android — APK из `eas build --profile preview`):

1. Открыть приложение без входа — видна главная, можно смотреть Маркет, Еду, Ивент; шапка сайта не под вырезом экрана.
2. Положить товар в корзину и начать оформление — сайт попросит войти (МТС ID или код из SMS), согласия.
3. После входа приложение один раз спросит разрешение на уведомления.
4. Подождать больше 15 минут (или свернуть приложение на час) — вход сохраняется, профиль и бонусы открываются.
5. Закрыть приложение полностью и открыть снова — вход сохраняется.
6. Оформить заказ Маркета и Еды (оплата при получении), увидеть их в профиле; бонусы в «Мои бонусы».
7. QR-код партнёра (Ивент → маршрут) — код вводится и засчитывается. Камерой телефона QR пока откроет браузер,
   не приложение (универсальные ссылки — М3).
8. Android: «Назад» закрывает открытый товар/корзину/категорию, с главной — выходит из приложения.
   Тёмная тема Android: текст в строке состояния (часы, батарея) виден.
9. Ссылки на Instagram / телефон / почту открываются в соответствующих приложениях, не внутри.
10. Режим полёта → «Нет соединения с интернетом» → включить сеть → «Повторить».
11. Выйти из профиля — следующий запуск без входа.

Уведомления о заказах сервер пока не отправляет (отдельный пакет на сервере) — на телефоне проверяется только
разрешение и регистрация.
